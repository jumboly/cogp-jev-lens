# タグ許可リスト・正規化辞書の生成
labels: design, data

## なぜ検討が必要か
1 回しか出ないペアが 191 万ある一方、上位 1 万ペアで出現の 91% をカバーする。
ビューポート内の全ユニークペアを無条件に JEV に送ると、ロングテール（タイポ・独自値）に無駄な評価が出る。

## 現在わかっていること
- 全世界の `key=value` 頻度表はプロファイリングで生成済み（`top_pairs_overall.csv` ほか）
- 正規化の要点: `;` 分解（`cuisine` は 68k → 13k 種）、`lower()`/`trim()`（効果は小さい）、`shop=yes` 等の種別不明値
- 許可リストは (a) タイポ排除、(b) 正規化、(c) 表示用説明文（OSM wiki）の付与、(d) 事前計算キャッシュの鍵、を兼ねられる

## 未決事項
- 閾値（世界で ≥N 件）。1〜2 万ペア（91〜93%）が目安
- 許可リスト外のペアの扱い: 評価しない / 低優先で評価 / キーだけで評価
- 静的 JSON として配布するか、BFF 側で持つか
- OSM wiki の説明文を機械的に取れるか（Taginfo API）
