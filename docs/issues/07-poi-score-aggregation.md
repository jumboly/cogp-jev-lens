# タグ評価から POI 評価への集約方法
labels: design, jev

## なぜ検討が必要か
JEV はタグ単位で評価するが、地図に出すのは POI。1 POI が持つ複数タグの評価をどう 1 つに畳むかで見え方が決まる。

## 現在わかっていること
- 候補: Noul（relevance）を重みにした Score の加重平均。Choice は確率分布を重み付き合成
- 半数の POI はタグ 1〜3 個。多くは「分類 1 つ + フラグ 1 つ」で、集約対象が少ない
- 主要分類キーを 2 つ以上持つ POI は 4.9%（`amenity` + `healthcare` が最多）
- フラグの意味は種別に依存する（`fee=no`）。単純加重平均だと種別と無関係に効く

## 未決事項
- relevance が全タグで低い POI（無関係）の扱い: 沈めるか、中立か
- 分類タグとフラグタグで重みの扱いを変えるか
- 集約をクライアント側で行う（タグ評価だけ BFF から返す）か、BFF 側で行うか
- JEV 出力の分布（中央寄り・二極化）次第で閾値・正規化が変わる → #3 の結果待ち

## 実験 01 からの示唆（2026-09-22）
- Noul を重みに使う案は見送り。Score の |Score−2| を relevance として使える
- `tourism=information`（案内板）が観光客 Lens で 3.90 と過大。細分タグ（`information=board`）の評価を分類タグより優先する集約が候補
- Score の全体分布は Lens で大きく動く（静か Lens は平均 1.36）。「2 = 変化なし」を固定アンカーにするか、Lens ごとに正規化するかは可視化側（#8）と合わせて決める
